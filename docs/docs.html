N.O.V.A.
Documentation

A fully local, voice and text controlled AI desktop assistant. Talk to it, type to it — NOVA understands intent, routes to the right module, responds through voice and a live chat window, recognizes faces, renders 3D models, and executes multi-step tasks in a single sentence.

What makes NOVA different
NOVA isn't a wrapper around a chatbot. It has a real multi-intent routing engine, persistent memory, 13 functional modules, 3 deep skills (face recognition, hand-gesture creative suite, text-to-3D generation), full GUI with system tray, and a first-time setup wizard. Built entirely in Python, runs locally.
Getting Started

Installation

1

Clone the repository

git clone https://github.com/shreyans-gits/voice-controlled-system
cd NOVA
2

Create a virtual environment (recommended)

python -m venv venv
venv\Scripts\activate
3

Install dependencies

pip install -r requirements.txt
4

Run the setup wizard

python setup.py

This opens a GUI where you enter your API keys and preferences. It generates your .env file automatically.

5

Launch NOVA

python nova.py
Windows Only
NOVA is built for Windows. System control (volume, brightness), pycaw audio, and system tray features are Windows-specific. Linux/macOS support is not guaranteed.

Architecture

How It Works

→You speak or type a query
→voice.listen() transcribes speech via Google Speech API, or text input is picked up from the GUI
→brain.get_intents() sends the query to Groq — returns a structured JSON list of intents with subjects and dependency links
→Independent intents (no dependencies) run in parallel via ThreadPoolExecutor
→Dependent intents run sequentially after their dependency completes, receiving output via IntentContext
→Each handler calls its module, puts result in the chat window, and speaks aloud
→If intent is CONVERSATION, the exchange is logged to memory
→On shutdown, Groq summarizes the session and merges it with past memory
→Next startup, the summary is injected into the system prompt — NOVA remembers you
Architecture

Multi-Intent Engine

NOVA can parse a single natural language query into multiple coordinated actions. The engine lives in brain.get_intents() and the executor in nova.py.

How it works

Each intent in the list has three fields: the intent name, an extracted subject, and an optional depends_on field. If depends_on is null, the intent is independent and can run in parallel. If it names another intent, it waits for that intent to finish and reads its output from the shared IntentContext object.

[
  {"intent": "GENERATE_MODEL", "subject": "castle", "depends_on": null},
  {"intent": "VIEW_MODEL",      "subject": "castle", "depends_on": "GENERATE_MODEL"}
]

Execution flow

→Split intent list into independent and dependent groups
→Independent group submitted to ThreadPoolExecutor — all run concurrently
→Executor waits for all parallel intents to complete
→Dependent intents run one by one, reading context.get_result() from the prior step

Example chains

QueryIntentsMode
"Check my CPU and tell me the weather"CPU + WEATHERParallel
"Generate a 3D castle and open it"GENERATE_MODEL → VIEW_MODELSequential (chained)
"Summarize my clipboard and send it to Tani"CLIPBOARD_EXPLAIN → WHATSAPPSequential (chained)
"Play Drake, check the weather, and read the news"SPOTIFY_PLAY + WEATHER + NEWSParallel
Fallback safety
If get_intents() fails to parse valid JSON from Groq, it automatically falls back to get_intent() and wraps the result in a single-item list. NOVA never crashes on a parse failure.

Architecture

Memory System

NOVA has persistent memory across sessions. It doesn't store raw logs — it uses Groq to compress conversations into a meaningful summary of who you are.

→During a session, CONVERSATION exchanges are logged in RAM via memory.log()
→On shutdown, memory.summarize_and_save(brain) sends the log to Groq
→Groq extracts key facts and merges them with the previous summary
→Final summary saved to memory.json — under 150 words
→Next startup, summary injected into the system prompt so NOVA already knows you
Clear memory
Say "clear your memory" or use the Settings window. This wipes both the session log and memory.json.
Modules

Core Modules

brain.py

The AI backbone. Handles multi-intent parsing, subject extraction, number extraction, conversation history, and session summarization. Uses Groq's Llama 3.3 70b model.

  • get_intents(query) → JSON list
  • get_intent(query) → single fallback
  • extract_subject(query, intent)
  • extract_number(query, intent)
  • ask(user_input)
  • summarize(log, old_summary)
context.py

The IntentContext object — a shared state container that travels between chained intent handlers. Enables output from one handler (e.g. a file path) to be consumed by the next.

  • set(key, value)
  • get(key, default)
  • set_result(value)
  • get_result()
memory.py

Manages persistent memory. Logs conversation exchanges during the session and compresses them into a summary on shutdown.

  • load() — reads memory.json
  • log(sender, text)
  • summarize_and_save(brain)
  • clear()
voice.py

Handles all audio I/O. Speech recognition via Google Speech API, TTS via Microsoft edge_tts with configurable voice and speed.

  • speak(text)
  • listen() → query string

Skills

FaceLink

Real-time face recognition integrated directly into NOVA's process. Uses the face_recognition library (dlib under the hood) with HOG detection and 128-dimensional embeddings.

How enrollment works

Faces are enrolled separately and stored as embedding vectors in data/enrolled_faces.pkl. At runtime, FaceLink loads this database once on init. Recognition is cosine similarity matching against the enrolled embeddings.

Two modes

identify() — single frame

Opens the webcam, captures one frame, detects all faces, matches against the enrolled database, releases the camera, and returns a list of recognized names to NOVA.

  • "Who is this?"
  • "Identify the person in front of me"
  • "Recognize this face"
open_live() — persistent view

Runs a full webcam loop in a daemon thread. Draws bounding boxes and name labels on every detected face at 1280×720. Runs every 5th frame for performance. Press Q to close.

  • "Open face recognition"
  • "Start facelink"
  • "Live face view"
Model spoof
FaceLink resolves its dlib model files dynamically from the active venv's site-packages at startup using a module-level spoof — no hardcoded paths required.
Skills

Gesture Suite

A full hand-tracking creative environment launched as a non-blocking subprocess. Built on MediaPipe hand landmarks, rendered via OpenCV at 1280×720.

How NOVA launches it

GestureModule in gesture.py resolves the absolute path to app.py and spawns it with subprocess.Popen, passing the target mode as arguments. NOVA stays fully responsive while the gesture window is open.

gesture.open_whiteboard()       # → app.py --mode whiteboard
gesture.open_voxel_editor()     # → app.py --mode shapes3d --sub 0
gesture.open_model(path)        # → app.py --mode shapes3d --sub 2 --file <path>

Tools

Whiteboard

Draw on a virtual canvas with your index finger. Left hand controls brush thickness via pinch spread. Both fists fill the canvas; open hands clear it.

  • "Open whiteboard"
  • Swipe down to change brush color
Voxel Editor

Build 3D voxel structures by pinching to place the first cube, then pinching with both hands to extend it in any direction. Rotate with index finger, select with cursor gesture.

  • "Open voxel editor"
  • Pinch to place, extend, select
3D Shapes Viewer

Renders wireframe 3D models. Supports a procedural sphere, Blockbench JSON, and OBJ files loaded via trimesh with automatic polygon decimation for models over 1200 faces.

  • "Show me the model"
  • Single finger to rotate
  • Pinch to translate, two hands to scale
Hand Gesture Controls

Swipe down (right hand in top zone) to open the sub-option panel. Index + middle finger cursor to hover-select. Swipe up to dismiss. Hover for 2 seconds to confirm selection.

  • Swipe down — open panel
  • Index + middle — cursor
  • Hover 2s — select
Skills

ModelGen

Text-to-3D generation via Shap-E running on a Google Colab notebook. Google Drive acts as the message bus between NOVA on your laptop and the Colab runtime.

Pipeline

→NOVA calls model_gen.generate("castle")
→Prompt sanitized → job_id = "castle"
→Job file uploaded to Google Drive with prompt + format
→Colab notebook picks up the job, runs Shap-E, uploads result OBJ
→drive_client.poll_for_result() polls Drive until result appears (up to 300s)
→OBJ downloaded to data/outputs/castle.obj, Drive file deleted
→Absolute file path returned to NOVA — or passed directly to gesture.open_model() if chained
Requires active Colab session
The Shap-E notebook must be running and watching the Drive folder for jobs. If it's not active, the request will time out after 300 seconds and NOVA will report the error aloud.

Chaining with VIEW_MODEL

The most powerful use of NOVA's multi-intent engine — one sentence generates and opens a 3D model:

"Generate a 3D model of a fire hydrant and show it to me"

→ GENERATE_MODEL(subject: "fire hydrant", depends_on: null)
→ VIEW_MODEL(depends_on: "GENERATE_MODEL")
   reads file path from IntentContext → gesture.open_model(path)

Contributing

Adding a new module or skill to NOVA follows a consistent pattern. Every handler is a standalone function registered in the INTENT_HANDLERS dict.

1

Create your module or skill file

Add a new file in modules/ (simple feature) or skills/ (complex integration with its own runtime). Create a class with an __init__ and the methods you need.

2

Add your intents to brain.py

Add your new intent word(s) to the valid intent list inside both get_intent() and get_intents() prompts. Add an example query to the few-shot examples in get_intents() if the intent has unusual chaining behavior.

3

Write a handler function in nova.py

Create a handle_your_feature(query, context, ...) function at module level. It should call your module, put results in message_queue, call voice.speak(), and optionally call context.set_result() if the output should be consumed by a downstream intent.

4

Register in INTENT_HANDLERS

Add a lambda to the INTENT_HANDLERS dict inside main() mapping your intent string to your handler function. The executor picks it up automatically — no changes to the main loop needed.
