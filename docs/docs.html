N.O.V.A.
Documentation

A fully local, voice and text controlled AI desktop assistant. Talk to it, type to it — NOVA understands intent, routes to the right module, responds through voice and a live chat window, recognizes faces, renders 3D models, executes multi-step tasks in a single sentence, and connects to your phone as a full bidirectional remote brain.

What makes NOVA different
NOVA isn't a wrapper around a chatbot. It has a real multi-intent routing engine, persistent memory, 13 functional modules, 3 deep skills (face recognition, hand-gesture creative suite, text-to-3D generation), a built-in FastAPI server, a full Android companion app with bidirectional audio and video, and a first-time setup wizard. Built entirely in Python, runs locally.
Getting Started

Installation

1

Clone the repository

git clone https://github.com/shreyans-gits/voice-controlled-system
cd NOVA
2

Create a virtual environment

python -m venv venv
venv\Scripts\activate
3

Install dependencies

pip install -r requirements.txt
4

Run the setup wizard

python setup.py

This opens a GUI where you enter your API keys and preferences. It generates your .env file automatically.

5

Launch NOVA

python nova.py

NOVA starts along with the FastAPI server on port 8000. No separate process needed.

Windows Only
NOVA is built for Windows. System control (volume, brightness), pycaw audio, and system tray features are Windows-specific.

Architecture

How It Works

→You speak or type a query — or send audio from the phone app
→brain.get_intents() sends the query to Groq — returns a structured JSON list of intents with subjects and dependency links
→Independent intents run in parallel via ThreadPoolExecutor
→Dependent intents run sequentially, receiving output via IntentContext
→Each handler calls its module, puts result in the chat window, and speaks aloud
→If the query came from the phone, the response is also returned over HTTP and spoken on the phone
→On shutdown, Groq summarizes the session and merges it into persistent memory
Architecture

Multi-Intent Engine

NOVA can parse a single natural language query into multiple coordinated actions. The engine lives in brain.get_intents() and the executor in nova.py.

Intent object structure

[
  {"intent": "GENERATE_MODEL", "subject": "castle", "depends_on": null},
  {"intent": "VIEW_MODEL",      "subject": "castle", "depends_on": "GENERATE_MODEL"}
]

Example chains

QueryIntentsMode
"Check my CPU and tell me the weather"CPU + WEATHERParallel
"Generate a 3D castle and open it"GENERATE_MODEL → VIEW_MODELSequential (chained)
"Summarize my clipboard and send it to Tani"CLIPBOARD_EXPLAIN → WHATSAPPSequential (chained)
Fallback safety
If get_intents() fails to parse valid JSON, it automatically falls back to get_intent() and wraps the result in a single-item list. NOVA never crashes on a parse failure.

Architecture

Memory System

→During a session, CONVERSATION exchanges are logged in RAM via memory.log()
→On shutdown, memory.summarize_and_save(brain) sends the log to Groq
→Groq extracts key facts and merges them with the previous summary — under 150 words
→Final summary saved to memory.json
→Next startup, summary injected into the system prompt so NOVA already knows you
Clear memory
Say "clear your memory", use the Settings window on desktop, or tap "WIPE MEMORY CORE" in the phone app settings — all three wipe both the session log and memory.json.
Modules

Core Modules

brain.py

The AI backbone. Handles multi-intent parsing, subject extraction, number extraction, conversation history, and session summarization. Uses Groq's Llama 3.3 70b.

  • get_intents(query) → JSON list
  • get_intent(query) → single fallback
  • extract_subject / extract_number
  • ask(user_input)
  • summarize(log, old_summary)
server.py

FastAPI server built into nova.py. Starts automatically on port 8000. Handles all phone app communication — audio transcription, query injection, response dispatch, video streams, and settings sync.

  • POST /api/mobile/process_audio
  • GET /api/mobile/video_feed
  • POST /api/mobile/upload_frame
  • GET /api/mobile/settings
  • POST /api/mobile/toggle_local_mic
context.py

The IntentContext object — a shared state container that travels between chained intent handlers. Enables output from one handler to be consumed by the next.

  • set(key, value) / get(key)
  • set_result(value)
  • get_result()
voice.py

Handles all audio I/O. Speech recognition via Google Speech API, TTS via Microsoft edge_tts. Thread-safe audio lock prevents overlapping playback. Respects local_mic_muted flag when phone app is active.

  • speak(text)
  • listen() → query string

Skills

FaceLink

Real-time face recognition integrated directly into NOVA's process. Uses the face_recognition library (dlib) with HOG detection and 128-dimensional embeddings. Face database stored in data/enrolled_faces.pkl.

identify() — single frame

Opens webcam, captures one frame, detects all faces, matches against enrolled database, returns names.

  • "Who is this?"
  • "Identify the person in front of me"
open_live() — persistent view

Runs a full webcam loop in a daemon thread. Draws bounding boxes and name labels on every detected face at 1280×720. Press Q to close.

  • "Open face recognition"
  • "Start facelink"
detect_and_identify_frame(frame)

Takes an externally provided OpenCV frame. Runs detection on a 0.25x scaled copy, matches against the enrolled database, returns scaled (location, name) tuples. Used by the phone reverse stream pipeline.

  • Called by server.py on each uploaded phone frame
  • Results overlaid live on browser view
Model spoof
FaceLink resolves its dlib model files dynamically from the active venv's site-packages at startup — no hardcoded paths.
Skills

Gesture Suite

A full hand-tracking creative environment launched as a non-blocking subprocess. Built on MediaPipe hand landmarks, rendered via OpenCV at 1280×720.

gesture.open_whiteboard()       # → app.py --mode whiteboard
gesture.open_voxel_editor()     # → app.py --mode shapes3d --sub 0
gesture.open_model(path)        # → app.py --mode shapes3d --sub 2 --file <path>
Whiteboard

Draw with index finger. Left hand controls brush thickness via pinch spread. Both fists fill canvas; open hands clear it.

  • "Open whiteboard"
  • Swipe down to change color
Voxel Editor

Build 3D structures by pinching to place the first cube, then pinching with both hands to extend in any direction.

  • "Open voxel editor"
  • Pinch to place, extend, select
3D Shapes Viewer

Renders wireframe 3D models. Supports procedural sphere, Blockbench JSON, and OBJ files via trimesh with auto polygon decimation for meshes over 1200 faces.

  • "Show me the model"
  • Single finger to rotate
  • Pinch to translate, two hands to scale
Gesture Controls

Swipe down to open sub-option panel. Index + middle finger as cursor. Hover 2 seconds to confirm selection. Swipe up to dismiss.

  • Swipe down — open panel
  • Index + middle — cursor
  • Hover 2s — select
Skills

ModelGen

Text-to-3D generation via Shap-E on Google Colab. Google Drive acts as the message bus.

→NOVA calls model_gen.generate("castle")
→Prompt sanitized → job uploaded to Google Drive
→Colab notebook runs Shap-E, uploads result OBJ
→Polls Drive until result appears (up to 300s timeout)
→OBJ downloaded to data/outputs/, Drive file deleted
→File path returned — or passed directly to gesture.open_model() if chained
Requires active Colab session
The Shap-E notebook must be running and watching the Drive folder. If inactive, the request times out after 300 seconds.

Voice Pipeline

→User unmutes mic on phone — laptop mic automatically muted via /api/mobile/toggle_local_mic
→PyAudio captures raw audio, amplitude-based silence detection compiles speech into a WAV file
→WAV POSTed to /api/mobile/process_audio
→Server transcribes via Google Speech API
→Query injected into NOVA's input queue with a request_id
→NOVA processes, handler returns response string, dispatched to _response_slots[request_id]
→Response returned over HTTP → shown in phone chat + spoken via TTS
→Laptop mic restored, phone audio loop restarts
Thread safety
A single-thread guard (_audio_thread_running flag) prevents multiple parallel audio capture threads from spawning — fixes the thread explosion bug from early testing.
Phone Link

Video Streams

Laptop → Phone (Webcam Monitor)

The webcam screen in the phone app connects to /api/mobile/video_feed. The server streams MJPEG frames from the laptop webcam. The phone parses JPEG boundary bytes, decodes frames, and renders them as Kivy textures. Screen automatically rotates to landscape on entry and back to portrait on exit.

Phone → Laptop (Roaming Eye)

Tapping the camera button on the dashboard triggers /api/mobile/start_reverse_stream, which opens a browser tab on the laptop at http://localhost:8000/mobile_camera. The phone captures frames via OpenCV, encodes as JPEG, and POSTs them to /api/mobile/upload_frame. The server runs FaceLink's detect_and_identify_frame() on each frame, overlays bounding boxes and names, and re-encodes for browser streaming.

FaceLink on phone camera
When the reverse stream is active, every uploaded frame is automatically passed through FaceLink. Recognized faces appear with green bounding boxes and names; unknown faces appear in blue. Results are also polled by the phone and spoken aloud every 3 seconds.

Phone App Setup

1

Configure Tailscale IP

Copy mobile_config.example.py to mobile_config.py and fill in your laptop's Tailscale IP.

LAPTOP_TAILSCALE_IP = "100.x.x.x"
2

Build the APK

cd phone_app
buildozer android debug

First build takes 20-30 minutes. APK appears in bin/.

3

Install on phone

buildozer android deploy run

Or copy the APK from bin/ and install manually.

4

Connect

Make sure both laptop and phone are on the same Tailscale network. Run python nova.py on the laptop — the FastAPI server starts automatically on port 8000.

mobile_config.py is gitignored
Never commit your Tailscale IP. Copy from mobile_config.example.py and fill in your own values locally.

Contributing

Adding a new module or skill follows a consistent pattern. Every handler is a standalone function registered in the INTENT_HANDLERS dict.

1

Create your module or skill file

Add a new file in modules/ (simple feature) or skills/ (complex integration). Create a class with an __init__ and the methods you need.

2

Add your intents to brain.py

Add your new intent word(s) to the valid intent list inside both get_intent() and get_intents() prompts.

3

Write a handler function in nova.py

Create a handle_your_feature(query, context, ...) function. It should call your module, put results in message_queue, call voice.speak(), and return the response string so network callers receive it.

4

Register in INTENT_HANDLERS

Add a lambda to INTENT_HANDLERS inside main(). The executor picks it up automatically — no changes to the main loop needed.
